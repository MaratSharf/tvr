# Обновлённый промпт для разработки программы контроля ширины нанесения мастики (замена ISRA)

## 🎯 Контекст проекта

Вы — разработчик системы машинного зрения. Вам необходимо создать программное обеспечение для промышленного ПК, которое заменит проприетарную систему ISRA BEADMASTER2D в роботизированной ячейке нанесения мастики (герметика). Программа должна захватывать изображения шва с помощью промышленной камеры, анализировать ширину и качество, и передавать результат роботу (KUKA KR200) через существующий интерфейс.

**Ключевое требование**: модуль связи с роботом должен быть **отдельным, заменяемым компонентом** (plug‑in), чтобы система могла работать с разными роботами и протоколами (PROFINET, Modbus TCP, OpenShowVar, EthernetKRL и т.д.). Это позволит использовать программу не только для KUKA, но и для других марок роботов, а также упростит тестирование на стенде.

**Тестовый стенд**:
- Для имитации сигналов робота используется **ОВЕН МК210** (контроллер с поддержкой Modbus TCP) с IP **192.168.1.99** и портом **502**.
- Камера Hikrobot имеет IP **192.168.1.36** (порт для связи по GigE Vision стандартный – обычно 80, но для конфигурации используется IP-адрес).
- На время тестирования **сигнал "начать измерение"** будет имитироваться **нажатием кнопки** (физической или программной на ПК). Результат измерения будет отправляться обратно в ОВЕН МК210 через Modbus TCP (запись в регистр) или отображаться на интерфейсе ПК.

## 📋 Общие требования к программе

### Оборудование и среда

- **Промышленный ПК**: Siemens SIMATIC IPC547G (Intel Core i5-6500, 16GB RAM, Windows 7 64-bit). (При необходимости можно использовать Linux, но в текущей конфигурации оставляем Windows 7.)
- **Камера**: Промышленная камера Hikrobot (например, серии MV-CS или MV-CA) с разрешением не менее 5 Мп, интерфейс GigE Vision. Подключается по IP **192.168.1.36**.
- **Освещение**: Кольцевой светодиодный источник с контроллером, обеспечивающий стабильную подсветку зоны контроля (≈100×100 мм) на рабочем расстоянии 100–120 мм.
- **Связь с роботом (основной способ)**: Интерфейсная плата **cifX PCI/PCIe** с драйверами для Windows 7, работающая в режиме PROFINET Device. Программа должна обмениваться данными с PLC/роботом через PROFINET.
- **Альтернативные способы связи (для заменяемости)**:
  - **Modbus TCP** (для тестового стенда с ОВЕН МК210 и для интеграции с другими контроллерами).
  - **OpenShowVar** (KUKAVARPROXY, порт 7000) – для простой связи с KUKA без PROFINET.
  - **EthernetKRL** (опционально, если лицензия приобретена).

### Функциональные требования

1. **Захват изображения**
   - Подключение к камере Hikrobot через MVS SDK.
   - Автоматическое обнаружение камеры по IP (или через поиск в сети).
   - Захват кадра по внешней команде (триггер от робота/PLC или имитация кнопкой).
   - Сохранение изображения для отладки (опционально).

2. **Обработка изображения (алгоритм компьютерного зрения)**
   - Предобработка (преобразование в градации серого, CLAHE, фильтрация).
   - Сегментация шва (бинаризация, морфологические операции).
   - Измерение ширины в нескольких точках или средней ширины.
   - Калибровка (пересчёт пикселей в миллиметры).
   - Обнаружение дефектов (разрывы, отклонение положения).
   - Принятие решения: **OK** (все параметры в норме) или **NOK** (выход за допуски или дефект).

3. **Взаимодействие с роботом/PLC (заменяемый модуль связи)**
   - Модуль связи должен быть реализован как **отдельный класс/модуль с чётким интерфейсом** (например, абстрактный базовый класс `RobotCommunicator` с методами `wait_for_trigger()` и `send_result(status)`).
   - Конкретные реализации:
     - **Profibus/PROFINET через cifX** – для работы с KUKA через существующую плату.
     - **Modbus TCP** – для тестового стенда с ОВЕН МК210 (и для потенциальной интеграции с другими PLC).
     - **OpenShowVar** – для простого обмена с KUKA через TCP/IP.
     - **EthernetKRL** – для официального решения KUKA.
   - Конфигурация выбирается через файл настроек (режим работы).
   - При запуске программа инициализирует выбранный модуль связи.

4. **Тестовый режим (для стенда)**
   - На время разработки и отладки триггер `wait_for_trigger()` должен возвращать `True` по нажатию кнопки (можно использовать клавиатуру или GUI-кнопку).
   - Результат (OK/NOK) должен отправляться в ОВЕН МК210 по Modbus TCP (запись в заданный регистр, например, `%MW0` или другой) и/или отображаться на экране ПК.
   - Возможность сохранять изображения и логи для верификации алгоритма.

5. **Конфигурация и параметры**
   - Конфигурационный файл (JSON/YAML) должен содержать:
     - Параметры камеры (экспозиция, усиление, IP).
     - Допуски по ширине (мин/макс) и калибровочный коэффициент.
     - Выбор режима связи и его параметры (IP, порт, номер регистра/переменной).
     - Пути для логирования и сохранения изображений.

6. **Логирование и диагностика**
   - Запись в лог-файл каждого измерения (время, ширина, статус).
   - Возможность визуализации (отображение обработанного изображения с размеченным швом) для отладки.
   - Обработка ошибок (потеря связи с камерой, таймауты) с автоматическим восстановлением.

7. **Сборка и развертывание**
   - Код пишется на **Python 3.8.10**.
   - Используемые библиотеки: OpenCV, NumPy, MVS SDK (Hikrobot), PyModbus (для Modbus TCP), PyInstaller.
   - Сборка в один `.exe` с упакованными зависимостями.
   - Автозапуск при старте Windows (через планировщик задач).

## 🧩 Архитектура модуля связи (заменяемый компонент)

Для обеспечения гибкости и возможности тестирования, модуль связи спроектирован следующим образом:

```python
# communication/base.py
from abc import ABC, abstractmethod

class RobotCommunicator(ABC):
    @abstractmethod
    def connect(self):
        """Установить соединение с роботом/PLC."""
        pass

    @abstractmethod
    def read_di(self, di_number):
        """Чтение дискретного входа (DI0-DI6)."""
        pass

    @abstractmethod
    def wait_for_di(self, di_number, timeout=None):
        """Ожидание активации DI с таймаутом."""
        pass

    @abstractmethod
    def send_result(self, status: bool):
        """
        Отправить результат измерения через DO.
        status: True = OK (DO3 зелёная), False = NG (DO2 красная).
        """
        pass

    @abstractmethod
    def reset_outputs(self):
        """Сброс всех дискретных выходов."""
        pass

    @abstractmethod
    def set_conveyor(self, on: bool):
        """Управление конвейером (DO0)."""
        pass

    @abstractmethod
    def send_do(self, do_number, value: bool):
        """Запись дискретного выхода по номеру."""
        pass

    @abstractmethod
    def disconnect(self):
        """Закрыть соединение."""
        pass
```

### Маппинг I/O ОВЕН МК210

| DI | Назначение          | DO | Назначение         |
|----|---------------------|----|--------------------|
| DI0| Датчик Д1 (конвейер)| DO0| Конвейер (пуск/стоп)|
| DI1| Датчик Д2 (камера)  | DO1| Толкатель (резерв)  |
| DI2| Датчик Д3 (камера)  | DO2| Лампа NG (красная)  |
| DI3| Датчик Д4 (выход)   | DO3| Лампа OK (зелёная)  |
| DI4| Тумблер A (старт)   |    |                    |
| DI5| Тумблер B (конец)   |    |                    |
| DI6| Датчик Д6 (захват)  |    |                    |

### Реализации:

1. **`ModbusCommunicator`** (для стенда и других контроллеров):
   - Использует `pymodbus`.
   - Подключается TCP к 192.168.1.99:502.
   - Чтение DI: регистр 51, биты di04=4, di05=5, di06=6.
   - Запись DO: регистр 470, биты do00-3.
   - `send_result(True)` → DO3 (зелёная), `send_result(False)` → DO2 (красная).
   - `reset_outputs()` → обнуляет регистр 470.

2. **`OpenShowVarCommunicator`**:
   - Raw socket клиент (pyopenshowvar отсутствует в PyPI).
   - Подключается к KUKAVARPROXY, порт 7000.
   - Чтение/запись переменных KUKA.

3. **`SimulationCommunicator`**:
   - Имитация DI/DO для тестирования без оборудования.
   - `wait_for_di()` возвращает True с задержкой.

Фабрика для создания нужного коммуникатора:
```python
def create_communicator(config):
    mode = config['communication']['mode']
    if mode == 'modbus':
        return ModbusCommunicator(config['communication']['modbus'])
    elif mode == 'openshowvar':
        return OpenShowVarCommunicator(config['communication']['openshowvar'])
    elif mode == 'simulation':
        return SimulationCommunicator(config)
    else:
        raise ValueError(f"Unsupported mode: {mode}")
```

## 🧪 Тестовый стенд (имитация робота)

На время разработки и отладки вы можете использовать **Modbus TCP** с контроллером **ОВЕН МК210** (IP 192.168.1.99). Сигнал "начать измерение" будет имитироваться нажатием кнопки на ПК (например, клавиша `Space` или GUI-кнопка). В этом случае:

- `wait_for_trigger()` может быть реализована как ожидание нажатия клавиши (для ручного режима) или чтение дискретного входа по Modbus (если кнопка подключена к МК210).
- `send_result()` будет записывать результат в Modbus-регистр (например, `%MW0`), чтобы ОВЕН МК210 мог его использовать для дальнейшей логики или отображения.
- Для дополнительной гибкости можно реализовать режим "симуляция", где триггер генерируется периодически или по таймеру.

## 🔧 Дополнительные требования к разработке

1. **Обработка ошибок**: Если связь с роботом/PLC потеряна, программа должна пытаться переподключиться (с заданным интервалом) и логировать ошибки. Если камера недоступна – аналогично.

2. **Скорость**: Цикл захват-обработка-отправка должен занимать **< 0.8 секунды** (учитывая движение 125 мм/с). При необходимости использовать многопоточность (асинхронный захват и обработка).

3. **GUI для отладки**: Желательно иметь простой графический интерфейс (например, на tkinter или PyQt), который показывает:
   - Живое изображение с камеры.
   - Результат измерения (OK/NOK, ширина).
   - Кнопку "Начать измерение" (для ручного режима).
   - Индикатор состояния связи.

4. **Калибровка**: Предоставить отдельный скрипт для калибровки, который позволяет вручную измерить эталон и сохранить коэффициент в конфигурацию.

5. **Документация**: В коде должны быть комментарии на русском или английском. Отдельный файл README с инструкцией по установке, настройке и запуску.

6. **Тестирование**: Предусмотреть возможность запуска в режиме "симуляция" без реальной камеры (использовать заранее сохранённые изображения), чтобы отлаживать логику без подключенного оборудования.
