# KODA.md — Контекст проекта «Система контроля шва»

## Обзор проекта

**Назначение:** Автоматизированная система визуального контроля ширины сварного шва на производственном стенде. Система работает в связке с промышленной камерой Hikrobot, контроллером ОВЕН МК210 (Modbus) и/или роботом KUKA KR200 (PROFINET).

**Тип проекта:** Python-приложение с графическим интерфейсом для инспекции изображений в реальном времени.

**Ключевые функции:**
- Захват изображения с камеры Hikrobot через Modbus TCP (триггер)
- Обработка изображения: выделение ROI, CLAHE, Otsu бинаризация, морфология, поиск контуров
- Измерение ширины шва в миллиметрах (калибровка px/mm)
- Управление промышленным оборудованием: конвейер, сигнальные лампы (OK/NG)
- Поддержка трёх режимов связи: Modbus TCP (ОВЕН МК210), PROFINET (KUKA KR200 через cifX), OpenShowVar (KUKA VARPROXY)
- Симуляционный режим для тестирования без оборудования
- Графический интерфейс (Tkinter) с живым видео, ROI-редактором, настройками и журналом событий
- Сохранение результатов и автоматическая очистка папок

**Целевая платформа:** Windows 7 / Промышленный ПК, Python 3.8.10.

## Архитектура

```
main.py              ← Точка входа, главный цикл инспекции
gui.py               ← Tkinter-интерфейс (старт/стоп, видео, ROI, настройки)
camera.py            ← Камера Hikrobot (Modbus-триггер, чтение папки изображений)
image_processor.py   ← Обработка изображений (измерение ширины шва)
roi_selector.py      ← Интерактивное выделение ROI (console + GUI)
config.json          ← Конфигурация (камера, ПЛК, калибровка, режим связи)

communication/       ← Абстракция связи с оборудованием
├── base.py          ← Абстрактный класс RobotCommunicator
├── factory.py       ← Фабрика коммуникаторов (по режиму из config)
├── modbus.py        ← Modbus TCP (ОВЕН МК210) — DI/DO, конвейер, лампы
├── profinet.py      ← PROFINET/cifX (KRC4, ISRA BEADMASTER2D протокол)
├── openshowvar.py   ← OpenShowVar (KUKAVARPROXY, сокеты)
└── simulation.py    ← Симуляция (тестирование без оборудования)
```

**Поток данных:**
1. Ожидание DI-сигналов (тумблер старт → датчик захвата → датчик конец)
2. Триггер камеры через Modbus → камера сохраняет фото в папку
3. Чтение последнего кадра → обрезка по ROI → обработка → измерение
4. Отправка результата (OK/NG) → управление DO (лампа зелёная/красная)
5. Цикл повторяется или сбрасывается

### Конфигурация

Файл `config.json` содержит все настройки:
- **camera:** IP камеры, выдержка, усиление, папка изображений, Modbus-параметры
- **seam_control:** границы ширины шва (мм), калибровка px/mm, порог бинаризации
- **communication:** режим (modbus/profinet/openshowvar/simulation), IP/unit, маппинг DI/DO
- **roi:** координаты зоны интереса (x, y, w, h)
- **storage:** лимиты очистки папок (max_files, max_age_days)
- **logging:** файл логов, уровень

## Правила разработки

### Стиль кодирования
- Язык комментариев и документации: **русский**
- Именование: `snake_case` для функций/переменных, `PascalCase` для классов
- Модульная структура: каждый компонент в отдельном файле
- Абстракция оборудования: `RobotCommunicator` с фабрикой — легко добавлять новые протоколы

### Тестирование
- **Симуляционный режим:** `communication/simulation.py` — позволяет тестировать весь пайплайн без оборудования
- Настроить `"communication": {"mode": "simulation"}` в `config.json`
- Симулятор генерирует тестовое изображение и имитирует DI/DO сигналы

### Калибровка
1. Сфотографировать объект известного размера (линейку)
2. Вычислить: `px_per_mm = пиксели / миллиметры`
3. Записать в `config.json.seam_control.px_per_mm`

### Работа с ROI
- Интерактивное выделение мышью через GUI (кнопка «ROI-зона»)
- Консольный режим: `python main.py --roi`
- ROI сохраняется в `config.json` атомарно (temp file + rename)

### Логирование
- Файл: `app.log` (RotatingFileHandler, 5 МБ, 3 бэкапа)
- Консоль: только WARNING и выше
- Структура: `%(asctime)s %(levelname)s %(name)s %(message)s`

### Безопасность и надёжность
- Атомарная запись `config.json` (temp file + os.replace)
- Повторные попытки отправки результата (1 retry)
- Гарантированный сброс всех DO при остановке (finally блок)
- Обрыв связи Modbus: автоматическое закрытие сокета + exponential backoff
- Очистка папок изображений по таймауту/лимитам

## Оборудование

### Камера Hikrobot
- IP: `192.168.1.36`
- Протокол: GigE Vision + Modbus TCP (порт 502)
- Требуется установленный MVS SDK

### Контроллер ОВЕН МК210 (Modbus)
- IP: `192.168.1.99`
- Порт: 502
- DI: датчики конвейера, тумблеры
- DO: конвейер, лампы OK/NG

### Робот KUKA KR200 (PROFINET)
- Драйвер: Hilscher cifX
- Протокол: ISRA BEADMASTER2D
- Имя устройства: `h901-200rb-100-kf084.m489g020s20-121-ml-3`

## Структура данных

### Результаты инспекции
- Папка: `data/results/`
- Формат имени: `{OK|NOK}_{timestamp}_{width}mm.png`
- Изображения с камеры: `data/images/foto/NG/`

### Логи
- Файл: `app.log` (корень проекта)
- Вращающийся: 5 МБ × 3 файла

## Расширение

### Добавление нового режима связи
1. Создать `communication/newprotocol.py` с классом, наследующим `RobotCommunicator`
2. Реализовать все абстрактные методы (`connect`, `read_di`, `send_result`, и т.д.)
3. Добавить режим в `communication/factory.py`
4. Добавить режим в `config.json.communication.mode`

### Добавление новых DI/DO
- Маппинг в `config.json.communication.modbus.di_map` и `do_map`
- Формат: `"di04": 4` — номер входа → бит в регистре
