# Описание алгоритма распознавания и измерения ширины шва

**Проект:** tvrus — замена системы ISRA BEADMASTER2D  
**Файл реализации:** `C:\proj\python\tvrus\image_processor.py` (класс `SeamProcessor`)  
**Язык:** Python 3.8.10+  
**Библиотеки:** OpenCV (`cv2`), NumPy  

---

## 1. Назначение

Автоматическая визуальная инспекция шва (мастики/герметика) на конвейерной линии с роботом KUKA.  
На вход поступает кадр с промышленной камеры Hikrobot, на выходе — вердикт **OK / NOK**, измеренная ширина шва в миллиметрах и расшифровка дефектов.

Алгоритм использует метод **поперечных секущих срезов (cross-slices)** вдоль осевой линии шва.

---

## 2. Общая схема обработки

```
Кадр с камеры
    │
    ▼
[Обрезка по ROI] → [Серый] → [Проверка контраста] ─┬─> Низкий контраст → ERR_NO_SEAM → NOK
    │                                                │
    ▼                                                ▼
[CLAHE (clipLimit=2.5)] → [Размытие 5×5] → [Бинаризация (Otsu / ручной порог, INV)]
    │
    ▼
[Маска игнорирования (Ignore Zones)] → [Авто-маска центрального паза (hole)]
    │
    ▼
[MORPH_CLOSE (морфологическое замыкание)] → [Заливка дырок от блика (glare fill)]
    │
    ▼
[Осевая линия шва: ручная разметка из эталона (равномерная интерполяция) ИЛИ автоматическая fitLine]
    │
    ▼
[Автопривязка оси к центру отверстия детали (только в режиме эталона, сдвиг ≤ 40 px)]
    │
    ▼
[Для каждого узла: сглаженная нормаль → поперечный срез → локальная защита от затенённого фона → runs → склейка блика → выбор лучшего run]
    │
    ▼
[Агрегация: медианная фильтрация ширин, средняя/мин/макс, fill_ratio, max_gap, 90-й перцентиль смещения]
    │
    ▼
[Проверка критериев брака: ERR_GAP, ERR_WID, ERR_POS, ERR_NO_SEAM]
    │
    ▼
Вердикт OK / NOK + ширина в мм + расшифровка ошибок
```


## 3. Подробное описание шагов

### Шаг 0. Кадрирование по ROI (зона интереса)

Перед обработкой изображение обрезается по заданной прямоугольной зоне интереса:

```
ROI = (x, y, w, h)
```

Координаты ограничиваются границами исходного кадра. Если ROI не задан (`None`), используется полное изображение. Смещение `(offset_x, offset_y)` запоминается, чтобы карты игнорирования и визуализация накладывались в правильных координатах исходного кадра.

### Шаг 1. Конвертация в градации серого

Если кадр цветной (BGR или BGRA), он конвертируется в одноканальное изображение оттенков серого:

```python
cv2.cvtColor(cropped, cv2.COLOR_BGR2GRAY)
```

### Шаг 2. Проверка контраста (защита от пустого кадра)

До основной обработки оценивается контраст внутри ROI:

1. Из серого изображения делается размытие по Гауссу `GaussianBlur(5×5)`.
2. Вычисляется стандартное отклонение яркости `contrast_std`.
3. Вычисляются 5-й и 95-й процентили яркости и их разница `contrast_range`.
4. Если **одновременно** `contrast_std < min_contrast_std` **и** `contrast_range < 2 × min_contrast_std` (по умолчанию порог `8.0`), кадр считается пустым или без шва.

**Результат:** ошибка `ERR_NO_SEAM`, цикл прерывается с вердиктом NOK.

Это защищает от ложных срабатываний, когда под камерой нет изделия, кадр пересвечен/подсвечен равномерно, или мастики нет вовсе.

### Шаг 3. Повышение контраста (CLAHE)

Применяется **CLAHE** (Contrast Limited Adaptive Histogram Equalization):

```python
clahe = cv2.createCLAHE(clipLimit=2.5, tileGridSize=(8, 8))
enhanced = clahe.apply(gray)
```

Это выравнивает локальный контраст, делая шов более заметным на фоне разного освещения. Значение `clipLimit=2.5` (смягченное относительно ранее использовавшегося 5.0), чтобы не пересвечивать продольный блик на мастике.

### Шаг 4. Размытие по Гауссу

К результату CLAHE применяется `GaussianBlur(5×5)` для подавления высокочастотного шума перед бинаризацией.

### Шаг 5. Бинаризация (Otsu или фиксированный порог)

Размытое изображение бинаризуется в инверсном режиме (`THRESH_BINARY_INV`), т.е. **тёмные объекты на светлом фоне становятся белыми (255), а фон — чёрным (0)**. Предполагается, что шов (мастика) темнее окружающей поверхности.

Два режима порога:
- **Otsu** (по умолчанию): порог выбирается автоматически алгоритмом Оцу, затем **смещается в сторону тёмных на 12%** (`tight_val = max(15, int(otsu_val × 0.88))`), чтобы бинаризация не захватывала полутени металла и бумаги по краям кадра.
- **Ручной**: фиксированное значение из `config` (`threshold`, по умолчанию 120).

### Шаг 6. Наложение маски игнорирования (Ignore Zones)

На бинарную маску накладываются пользовательские зоны игнорирования (`ignore_rects`) — прямоугольные области, которые закрашиваются чёрными (0). Они используются для маскирования бликов, отверстий, резьбы или иных артефактов, которые могут быть ошибочно приняты за шов.

**Контракт координат.** ROI задаётся в координатах исходного кадра. Внутри обработанного ROI (уже обрезанного кадра) центральная линия, маски игнорирования и измерения работают в **локальных координатах ROI** (0..w, 0..h). Точки эталона (`centerline_px`) и прямоугольники `ignore_rects` хранятся в sidecar JSON именно в локальных координатах — `gui.py` обрезает кадр по ROI **до** передачи его в `EtalonAnnotator`. Метод `_to_local_coords` считает координаты эталона уже локальными и не делает дополнительного сдвига на `offset_x/offset_y`. Перед отрисовкой на полном кадре координаты переводятся обратно в глобальные (`lx + roi_x`, `ly + roi_y`).

### Шаг 6b. Автоматическая маска центрального паза (auto_mask_hole)

Сквозное отверстие (паз) в центре детали имеет очень низкую яркость и маскируется автоматически, чтобы не мешать измерению:

1. Пороговая фильтрация исходного размытого серого изображения по `hole_threshold` (по умолчанию 28) в инверсном режиме — получается «тёмная маска».
2. Эрозия эллиптическим ядром радиуса `max(5, max_width_mm × px_per_mm × 0.35)` — убираются мелкие тёмные точки на металле и узкий край герметика.
3. Поиск контуров; отбираются контуры площадью больше `(max_width_mm × px_per_mm)² × 0.5`.
4. Найденные отверстия дилатируются эллиптическим ядром с запасом +12 px (на темную фаску паза).
5. Область отверстия зануляется на бинарной маске шва.

Отключается опцией `auto_mask_hole = false`.

### Шаг 6c. Автопривязка оси к центру отверстия детали (shape alignment)

Чтобы измерения не «плыли» при горизонтальном/вертикальном сдвиге детали на конвейере relative к фиксированному ROI, эталонная ось может быть смещена по вектору смещения центрального отверстия:

1. На сером изображении (после Гаусса) ищутся тёмные пиксели (`< hole_threshold`) через инверсную пороговую фильтрацию и `MORPH_OPEN` эллипсом 11×11.
2. Выбирается наибольший контур — ожидается, что это сквозное отверстие (паз) в центре детали.
3. Вычисляются моменты контура `cv2.moments`; если площадь `m00` слишком мала (< 100 px) или контура нет — привязка отменяется, ось остаётся без сдвига.
4. Центр найденного отверстия сравнивается с центром масс точек эталонной оси (`centerline_px`). Вектор сдвига `(dx, dy)` ограничивается ±40 пикселей — при большем смещении привязка считается недостоверной и отменяется (предупреждает «прыжок» оси на посторонний тёмный объект).
5. Все точки оси сдвигаются на вектор `(dx, dy)` до построения поперечных срезов.

Применяется **только при активной эталонной аннотации** (`self.centerline_px` задан). В автоматическом режиме (`fitLine`) привязка не делается.

### Шаг 7. Морфологическое замыкание (MORPH_CLOSE)

Применяется морфологическая операция `MORPH_CLOSE` (дилатация затем эрозия) с прямоугольным ядром размера `morph_kernel_size × morph_kernel_size` (по умолчанию `3×3`; если чётное — приводится к нечётному).

Цель: замыкание мелких разрывов внутри тела шва, устранение дыр, сглаживание контура, чтобы шов стал сплошной белой областью.

### Шаг 7b. Заливка дырок от блика (_fill_specular_glare)

Продольный блик на гребне мастики может создать черную дыру (0) внутри белого контура шва (255). Для этого:

1. Строится иерархия контуров `RETR_CCOMP` (внешние контуры + внутренние полости).
2. Внутренние контуры (дети, `hierarchy[i][3] != -1`) площадью меньше `(max_width_mm × px_per_mm)² × 4.0` закрашиваются обратно в 255.

Отключается опцией `fill_glare_holes = false`.

### Шаг 8. Построение осевой линии шва (centerline)

Ось шва — ломаная линия, проходящая по центру шва. Может быть задана двумя способами:

#### А) Ручная разметка (эталон) — предпочтительный режим
Пользователь в GUI наносит полилинию по центру эталонного шва (инструмент «Траектория шва» в `EtalonAnnotator`). Координаты точек сохраняются в sidecar JSON эталона и загружаются в `SeamProcessor` через `set_etalon_annotation`. При запуске инспекции в режиме «Инспекция по эталону» (`train_mode_var == 'verify'`) GUI автоматически ищет самый свежий эталон с меткой `ok` для выбранного ProductID, загружает его `centerline_px`, `ignore_rects`, `step_px`, `max_allowed_gap_mm`, `pos_tolerance_mm` и метрики (`gui.py: _apply_active_etalon_to_processor`). Заданная ломаная приводится к равномерному шагу методом `_resample_polyline` (точки ставятся каждые `step_px` пикселей вдоль всей длины ломаной с учётом фактической длины каждого сегмента; конечная точка включается). Это критически важно для корректного расчета длины разрывов на U-образном шве — иначе длина цепочки gap-срезов (`max_gap_mm`) считалась бы по хордам, а не по дуге.

#### Б) Автоматический режим (fitLine)
Если ручная разметка отсутствует, ось строится автоматически:
1. На очищенной бинарной маске ищутся контуры (`cv2.findContours`, `RETR_EXTERNAL`).
2. Выбирается наибольший по площади контур (предполагается, что это шов).
3. Точки контура преобразуются в массив `float32`.
4. По всем точкам строится регрессионная прямая методом `cv2.fitLine` (метод наименьших квадратов, дистанция L2).
5. Прямая параметризуется, и по ней с шагом `step_px` (по умолчанию 15 px) выбираются промежуточные точки — это и есть узлы осевой линии.

**Ограничение:** `fitLine` строит одну прямую, что не подходит для U-образных траекторий. Для криволинейных швов обязательна ручная разметка эталона. В производственном режиме без валидной эталонной аннотации ось считается недостоверной.

Для вычисления нормали используются соседние точки:
- Для внутренних точек: нормаль к отрезку между **предыдущей** и **следующей** точкой оси (сглаживание по соседям — плавный проход U-образной дуги без рывков нормали).
- Для первой/последней точки: нормаль к отрезку между двумя крайними доступными узлами.
- Участки с почти совпадающими точками защищаются проверкой длины отрезка (`max(1e-6, ...)`).

### Шаг 9. Поперечные срезы (normal slices)

Для каждого узла осевой линии строится нормаль — единичный вектор, перпендикулярный направлению шва в этой точке:

- Для внутренних точек: нормаль к отрезку между **предыдущей** и **следующей** точкой оси (сглаживание по соседям — плавный проход U-образной дуги без рывков нормали).
- Для первой/последней точки: нормаль к отрезку между двумя крайними доступными узлами.

Длина полусреза рассчитывается от физических размеров:

```
search_margin_mm = min(pos_tolerance_mm, 1.2)
physical_half_len = (max_width_mm × 0.55 + search_margin_mm) × px_per_mm
half_length = max(25, step_px × 1.5, physical_half_len)
```

Так срез гарантированно перекрывает максимальную ширину шва и допуск позиции, но не улетает на 300+ пикселей в затенённый фон по краям ROI (раньше величина доходила до 320 px и вызывала «прострелы» на изгибах).

### Шаг 10. Измерение ширины белого участка (_slice_width)

Для каждого среза извлекается профиль яркости вдоль нормали к оси в пределах `half_length` с каждой стороны. Ширина ищется не по самому длинному белому участку без проверок, а с достоверной сегментацией:

1. **Сегментация для измерения**: перед измерением к бинарной маске `seg` (уже с наложенными ignore-зонами и маской паза) применяется `_fill_specular_glare` — заливаются только те внутренние полости, которые обоснованно являются бликом внутри валика шва (полностью окружены швом, не касаются границ кадра, не уже одного поперечного размера, лежат в коридоре вокруг оси). Исходная маска без заливки сохраняется для анализа разрывов, чтобы морфология не склеивала реальные разрывы.
2. По срезу собираются значения бинарной маски (`seg_measure`) и исходного серого изображения (`gray`).
3. **Устойчивая оценка фона**: `bg` — 75-й процентиль сглаженного профиля серого (ядро [0.25, 0.5, 0.25]). Медиана по краям не используется: на U-образном шве край среза может попадать на тень, а фон оценочно завыжался бы.
4. Белые пиксели `seg` группируются в непрерывные отрезки (runs). Узкие разрывы между runs (≤ `max_width_mm × 0.40 × px_per_mm` px), внутри которых яркость выше краев (блик на гребне), склеиваются.
5. Темнота шва оценивается как `bg − 10-й процентиль серого по белым пикселям seg`.
6. Из оставшихся runs выбирается лучший по скорингу:
   - run обязан либо содержать ось среза (`t = 0` внутри `[t_start, t_end]`), либо его центр должен лежать в пределах `min(pos_tolerance_mm, 1.5) × px_per_mm` от оси;
   - отсекаются удалённые run (посторонние объекты: кромка отверстия, тень сопла);
   - скоринг: `score = 1000 (если содержит ось) − 1.5 × |смещение_центра| + 0.5 × темнота + (15 − штраф_по_ширине)` — приоритет участку, содержащему ось, без аномального смещения.
7. Ширина в пикселях: `width_px = best_end − best_start`. Пересчёт в миллиметры: `width_mm = width_px / px_per_mm`.
8. Проверки достоверности:
   - `contrast_ok`: темнота шва и контраст граней ≥ `min_edge = max(6, edge_contrast_min × 0.5)`;
   - `width_plausible`: ширина в пределах `[gap_min_width_mm × 0.75, max_width_mm × 2.0]` в пикселях;
   - `offset_ok`: смещение центра run от оси ≤ `pos_tolerance_mm × px_per_mm + max_width_mm × 0.5 × px_per_mm`.
9. Если белых пикселей нет, или подходящий run не найден, или любая проверка достоверности не пройдена — срез помечается **разрывом (gap)** или **недостоверным (invalid)**. Отсутствие границ не подменяется искусственно восстановленной шириной.

Итоговое поле `confidence` (0..1) складывается из вкладов: темнота (до 0.4), plausible ширина (0.3), смещение в допуске (0.3).


### Шаг 11. Агрегация метрик по всем срезам

После прохождения всех узлов оси вычисляются:

| Метрика | Описание |
|---------|----------|
| `mean_width_mm` | Средняя ширина по валидным срезам (исходные измерения, медианная фильтрация окном 3 — только для отчёта) |
| `min_width_mm` | Минимальная ширина по исходным измерениям (включая края массива) |
| `max_width_mm` | Максимальная ширина по исходным измерениям (включая края массива) |
| `fill_ratio` | Доля валидных срезов от проверяемых (проверяемые = всего − исключённые ignore-зонами) |
| `max_gap_mm` | Максимальная длина непрерывной цепочки gap-срезов в мм по накопленному расстоянию вдоль оси |
| `expected_length_mm` | Ожидаемая длина шва (сумма длин сегментов полилинии в мм) |

**Медианная фильтрация**: если неразрывных срезов ≥ 5, ширина каждого внутреннего среза заменяется медианой окна 3 (срезы `i−1, i, i+1`), после чего `mean/min/max` считаются от отфильтрованного массива; `min/max` дополнительно исключают первый и последний элемент (крайние срезы на границах шва дают завышенные/заниженные значения).

**Адаптивный порог валидности**: результат считается недостоверным (`ERR_INVALID`), если валидных измерений меньше `max(3, 10 % от числа узлов оси)`. Для U-образных швов с десятками срезов фиксированное значение «3» было бы избыточно строгим.

Если **все** проверяемые срезы — разрывы, ставится `ERR_NO_SEAM` (шов не найден), а не `ERR_INVALID`.

## 4. Критерии брака (коды ошибок)

Используются биты ошибок, которые могут комбинироваться (битовая маска):

| Код | Название | Условие срабатывания |
|-----|----------|----------------------|
| `ERR_NONE` = 0 | Нет ошибок | Все проверки пройдены |
| `ERR_GAP` = 1 | Разрыв | `max_gap_mm > max_allowed_gap_mm` **ИЛИ** `fill_ratio < min_fill_ratio` |
| `ERR_WID` = 2 | Ширина | `min_width < min_width_mm` **ИЛИ** `max_width > max_width_mm` |
| `ERR_POS` = 4 | Позиция | 90-й перцентиль `\|offset_mm\|` (при ≥ 5 срезах, иначе среднее) > `pos_tolerance_mm` |
| `ERR_NO_SEAM` = 8 | Шов не найден | Все срезы разрывные **ИЛИ** не найдена ось **ИЛИ** низкий контраст |

Проверка позиции использует **90-й перцентиль** (а не простое среднее), чтобы ловить локальный уход шва на дуге — одиночные выбросы не «размазывают» среднее, но критический уход на 10% срезов фиксируется.

## 5. Итоговый вердикт

```python
ok = (error_code == ERR_NONE)
```

- Если `ok == True` → шов считается годным (**OK**), зажигается зелёная лампа (DO3).
- Если `ok == False` → брак (**NOK**), зажигается красная лампа (DO2). В сообщении перечислены все сработавшие критерии через точку с запятой.

## 6. Режимы работы и обучение (эталон)

Система поддерживает два режима:

### Режим production (рабочий)
Используется конфиг из `config.json` с фиксированными допусками ширины и позиции. Ось шва строится автоматически (`fitLine`) — пригодна только для почти-прямых траекторий.

### Режим «Инспекция по эталону» (verify)
При переключении радиокнопки на «Инспекция по эталону», при смене ProductID в выпадающем списке, при старте инспекции и после сохранения нового эталона GUI вызывает `_apply_active_etalon_to_processor(processor)`:

1. Ищет самый свежий эталон со статусом `ok` для выбранного ProductID в `EtalonStore` (`scan_etalons` / `load_etalon`).
2. Проверяет наличие `annotation.centerline_px` (≥ 2 точек).
3. Загружает в `SeamProcessor` через `set_etalon_annotation`: `centerline_px`, `ignore_rects`, `step_px`, `max_allowed_gap_mm`, `pos_tolerance_mm`, `metrics`.
4. В журнале GUI пишется `Загружен эталон [ProductID]: ET_... (точек оси: N, масок IGNORE: M)`; если эталона нет — предупреждение и сброс аннотации (`clear_etalon_annotation`), работа продолжается в автоматическом режиме.

### Режим обучения / редактирования эталона
Через GUI пользователь может:

1. Зафиксировать кадр с хорошим швом.
2. Нарисовать осевую линию шва вручную (инструмент «Траектория шва»).
3. Обозначить зоны игнорирования (блики, отверстия).
4. Задать шаг срезов, допустимый разрыв и допуск позиции.
5. Сохранить эталон с метриками в папку `data/etalon/<product_id>/` (изображение + sidecar JSON).
6. При повторной загрузке эталона алгоритм использует размещенную ось вместо автоматической `fitLine`.

**Важное исправление сохранения:** при нажатии «Атомарно сохранить эталон» без предварительной нажатой кнопки «Проверить разметку» аннотатор (`etalon_annotator.py: _save_etalon`) автоматически вызывает `_preview_check()`, чтобы метрики шины рассчитались до записи JSON (раньше эталон сохранялся с шириной `— mm` / `0.00 мм`).

Также реализован расчёт автодопусков по медиане и MAD (среднее абсолютное отклонение) по набору эталонам с меткой `ok`, что позволяет подобрать рекомендуемые `min_width` / `max_width` на основе фактической статистики выпуска.

## Исправления производительности и взаимодействия с GUI

- **`main.py: grab_image()`** — неподвижная пауза `time.sleep(0.3)` и шаг опроса `0.2 с` сокращены до `0.05 с` (камера сохраняет JPEG за ~100–200 мс). Время цикла `Capture processing` падает с ~0.813 с до ~0.25–0.35 с, укладываясь в бюджет 0.8 с.
- **`gui.py`** — добавлен метод `_apply_active_etalon_to_processor()`, который загружает разметку эталона в `SeamProcessor` при старте инспекции (`_worker`), при переключении радиокнопок (`_on_train_mode_change`), при смене ProductID (биндинг `<<ComboboxSelected>>`) и после сохранения эталона (`_on_etalon_saved`). Раньше эталон never передавался в процессор, и всегда работал автоматический `fitLine`.
- **`etalon_annotator.py`** — `_save_etalon()` автоматически вызывает `_preview_check()`, если метрики ещё не посчитаны, чтобы эталон не сохранялся с прочерком `— mm`.
- **`image_processor.py`** — `_to_local_coords()` теперь считает координаты эталона уже локальными к ROI (двойной сдвиг убран); порог Otsu смещён на 12% в тёмную сторону; коридор среза сужен (`max_width × 0.55 + min(pos_tolerance, 1.2)`); `_slice_width()` защищён локальным порогом яркости от затенённого фона; добавлена автопривязка оси к центру отверстия детали (±40 px).

## 7. Ограничения и допущения
1. Шов должен быть **темнее** фона (иначе нужно изменить направление бинаризации, убрав `THRESH_BINARY_INV`).
2. Ось шва должна быть относительно прямой на участке ROI (автоматический `fitLine` строит одну прямую; для сильно изогнутых швов требуется ручная полилинейная разметка).
3. Точность измерения зависит от калибровки `px_per_mm` (количество пикселей на 1 мм), которую нужно определить опытным путём на объекте.
4. Цикл обработки должен укладываться в **< 0.8 секунд** (требование производительности конвейера при скорости робота 125 мм/с).
5. Разработка ведётся под Python 3.8.10 (последняя версия, поддерживающая Windows 7).
