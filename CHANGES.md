## 4. Открытые вопросы (требуют решения на стенде)

1. **Modbus `unit`** — ИСПРАВЛЕНО И ПРОВЕРЕНО НА СТЕНДЕ (2026-10-20): рабочее значение **unit=1** (OWEN MK210: FC3@51 → 0x0003, FC3@470 → 0x0000; с unit=0 контроллер не отвечает вовсе). В `config.json` для ПЛК и камеры стоит `1`. Первопричина: `device_id` в pymodbus 2.5.3 игнорируется, в эфир уходил `unit_id=0`.
2. **Порядок протокола**: код ждёт DI05 и только потом шлёт результат; документация описывает «результат → DI05». Нужна сверка со сканером протокола KRC4 (`DAI_KNI.SRC`).
3. **Алгоритм ширины шва**: сейчас `min(w,h)` габаритного бокса контура — не минимальная ширина вдоль оси шва. Риск ложного OK при локальных сужениях. Менять только после калибровки на реальных швах.
4. **Поведение при отказе камеры**: конвейер продолжает движение, детали проходят без измерения до DI05 (NG приходит в конце цикла). Решить, останавливать ли конвейер при отказе триггера.
5. **FC3 vs FC4**: входной регистр 51 читается функцией FC3 (holding). Работает на стенде, но сверить с документацией OWEN на предмет «input register».

## 6. Диагностика на реальном железе (2026-10-20)

### 6.1 Что обнаружено
- **Камера**: Hikrobot **MV-SC3016C-06M-WBN** @ 192.168.1.36, разрешение **1408×1024** (а не 1024×1408 — ориентация горизонтальная), `ExposureTime=36218 мкс`, `Gain=3.9`, **`TriggerMode=Off` (free-run)**.
- **Modbus-триггер камеры РАБОТАЕТ** (проверено 2026-10-20, 5/5 срабатываний): камера — **смарт-камера** со встроенной программой контроля, Modbus-сервер живёт независимо от MVS-захвата. Ранее `trigger_ready=0` был временным состоянием. Протокол — см. 6.5.
- **Кадры в папке пишет камера по триггеру**: удалённое приложение на 192.168.1.36 держит камеру (MVS SDK) и заливает кадры по **FTP** в `data/images/foto/NG` (~1 кадр/с в режиме free-run); после перевода стенда в триггерный режим фоновый поток остановлен (0 файлов за 10 с), каждый триггер даёт ровно один новый кадр. Папка = источник изображений; FTP-сервер (FileZilla Server) крутится на этой машине.
- **Побочный эффект диагностики**: эксклюзивный захват камеры на ~10 с остановил FTP-поток; удалённое приложение переподключилось само (поток восстановился).
- **ПЛК**: OWEN MK210 @ 192.168.1.99 работает с **unit=1**; регистр 51 (FC3) = 0x0003, регистр 470 (FC3) = 0x0000. С unit=0 контроллер молчит.
- **Частичная запись JPEG**: OpenCV возвращает частично декодированный кадр с C-уровневым предупреждением «Premature end of JPEG file», а не `None` — **исправлено**: добавлена проверка маркера конца файла в `camera._is_file_complete()` (JPEG EOI / PNG IEND).

### 6.5 Протокол Modbus-триггера камеры (восстановлен эмпирически)

Камера — смарт-камера MV-SC3016C, Modbus TCP :502, **unit=1**, байты little-endian.

| Reg | Назначение |
|-----|-----------|
| 0 | control (запись) |
| 1 | status (биты триггера) |
| 2 | код результата (напр. 3) |
| 3–4 | строка результата ASCII (напр. `"NG;"`) |

**Биты status (reg 1)**: `0x0001` trigger_ready, `0x0002` trigger_ack, `0x0004` acquiring, `0x0008` decoding, `0x0100` results_available, `0x0200` results_timeout, `0x0400` command_ok, `0x0800` command_failed, `0x8000` general_fault.

**Последовательность** (реализована в `camera.py::trigger_capture`):
1. `write reg0 = 0x8000` (reset), `write reg0 = 5` → status = `0x0001` (ready);
2. `write reg0 = 1` (Trigger Enable) → ждём бит `0x0001` (~3 мс);
3. `write reg0 = 3` (Trigger) → ждём бит `0x0100` (~117–157 мс; не более `trigger_timeout`); ошибки `0x0200`/`0x0800` → лог и отказ;
4. `write reg0 = 5` (отключение) → кадр уже в папке.

Замеры: ready 3 мс, триггер 117–157 мс (5/5 безотказно), полный `trigger_capture` 292–353 мс после уменьшения фиксированных пауз (0.2/0.2/0.1 → 0.05/0.05/0.02).

## 7. Графический интерфейс (2026-10-21)

Новый файл `gui.py` — Tkinter GUI (встроен в Python 3.8, новых зависимостей нет). Запуск: `python gui.py` или `python main.py --gui`.

### 7.1 Возможности
- **Старт/Стоп** — рабочий цикл в фоновом потоке; остановка оператором за ~1 с через чек-флаг, конвейер останавливается, выходы сбрасываются, результат в этот момент не отправляется (разрыв цикла — не авария).
- **Панель управления** — кнопки Старт/Стоп, индикатор РАБОТА/СТОП, режим связи.
- **Видео** — живой кадр с наложенным результатом (BGR→RGB→PNG→`tk.PhotoImage`), адаптация под размер окна.
- **Панель результата** — крупный OK/NOK (зелёный/красный), ширина шва, время, счётчики OK/NOK/всего, текущий ROI.
- **ROI-редактор** — выделение зоны мышью на canvas (масштабируется под кадр, показ размера в px), сохранение через `ROIManager.save_to_config` (атомарно) + живое обновление `processor.set_roi` без перезапуска. Кадр берётся из последнего кадра инспекции или загружается из папки камеры (`_read_latest_from_folder` без соединения).
- **Настройки** — режим связи, IP/unit камеры и ПЛК, `px_per_mm`, границы ширины, лимит цикла; валидация (числа > 0, min < max, IP не пустой), атомарная запись config.json, применение к живому `SeamProcessor` на лету.
- **Журнал** — статусы цикла и записи logging в одном окне (ERROR/CRITICAL — красным, WARNING — оранжевым), ротация при 1000 строк; `QueueLogHandler` доставляет записи из рабочего потока в очередь.

### 7.2 Рефакторинг `main.py` (совместимость сохранена)

## 8. Переработка алгоритма `image_processor.py` (2026-10-27)

Полная замена метода измерения ширины: вместо `min(w,h)` габаритного бокса контура — метод поперечных секущих срезов (`SeamProcessor.process()`). Старый код сохранён в `image_processor_old.py`.

### 8.1 Что изменилось
- **Срезы вместо бокса**: ось шва (эталонная полилиния с равномерной интерполяцией `_resample_polyline` или автоматический `cv2.fitLine`) разбивается на узлы с шагом `step_px`; в каждом узле по сглаженной нормали (по соседним узлам — плавный проход U-образной дуги) измеряется ширина белого участка.
- **Выбор run в срезе** (`_slice_width`): все непрерывные белые отрезки → склейка пар, разделённых бликом (яркий пик между краями) → отсечение посторонних объектов по коридору `pos_tolerance + max_width/2` → скоринг `width − 0.5·|offset|` вместо «просто самого длинного».
- **Авто-маска центрального паза** (`_mask_central_hole`): сквозное отверстие (яркость < `hole_threshold`) эродируется, детектируется по площади, дилатируется с запасом на фаску и зануляется. Опции: `auto_mask_hole`, `hole_threshold` (28).
- **Заливка дырок от блика** (`_fill_specular_glare`): внутренние полости контура (RETR_CCOMP) площадью < `(max_width·px_per_mm)²·4` закрашиваются обратно в белое. Опция: `fill_glare_holes`.
- **Медианная фильтрация ширин** (окно 3, при ≥5 срезах) перед агрегацией — убирает одиночные выбросы; `min/max` считаются без крайних срезов.
- **Проверка позиции по 90-му перцентилю** `|offset_mm|` (вместо среднего) при ≥5 неразрывных срезах — ловит локальный уход шва на дуге.
- **Длина полусреза от физики**: `max(25, step_px·1.5, (max_width·0.65 + pos_tolerance)·px_per_mm)` — срез всегда перекрывает максимальную ширину.
- **CLAHE `clipLimit=2.5`** (вместо 5.0) — не пересвечивает блик на мастике; убран `MORPH_OPEN`.
- **Битовые коды ошибок** `ERR_GAP/ERR_WID/ERR_POS/ERR_NO_SEAM` и `detail`-словарь (slices, centerline, fill_ratio, max_gap_mm, annotated_image) вместо `bbox`.
- **Визуализация** `draw_result`: ось, цветные срезы (ok/green, wid/yellow, gap/red), зоны IGNORE, коды ошибок; `draw_result_backward_compat` для старой сигнатуры.
- **Защита координат ROI** (`_to_local_coords`): умный перевод глобальных/локальных координат разметки при кадрировании.
