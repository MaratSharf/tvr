

# Подробный итоговый конспект-инструкция
## Замена системы ISRA на собственную систему контроля шва мастики
### на базе промышленной камеры Hikrobot и ПК Siemens IPC547G (Windows 7)

---

## 1. Введение и анализ существующей системы

**Цель проекта** – разработать и внедрить собственную систему контроля качества нанесения мастики (герметика) на роботизированной ячейке KUKA, заменив проприетарную систему ISRA BEADMASTER2D. Система должна выполнять захват изображения шва, его анализ и передачу результата (OK/NOK) роботу для управления процессом.

**Существующая система** (по документации):
- **Робот**: KUKA KR200, контроллер KRC4.
- **Программное обеспечение**:
  - `HP001.src` – главный диспетчер, управляющий последовательностью операций по сигналам PLC.
  - `KLBML200R1Z539417100202.src` – подпрограмма нанесения клея (содержит вызовы `DAI_KNI` для управления ISRA).
  - `SHOW_POSITION.src` – сервисный модуль для калибровки.
- **Интерфейс с ISRA**: через дискретные входы/выходы (лист `ISRA_ROBOT` в Excel):
  - `$OUT[1719]` – Measurement Start (запуск захвата кадра).
  - `$IN[1705…1719]` – статусы (Operational, Passed, Width Error, Seam Error и т.д.).
- **Оборудование ISRA**:
  - Промышленный ПК Siemens SIMATIC IPC547G (i5-6500, 16GB, Windows 7).
  - Датчик BEADMASTER2D: 3 камеры + подсветка, FOV 100×100 мм, рабочее расстояние 100–120 мм, скорость контроля 125 мм/с.
  - Интерфейсная плата **cifX PCI/PCIe** для PROFINET (связь с PLC и роботом).

**Задача**: сохранить ПК и, по возможности, часть оборудования, но разработать собственное ПО для обработки изображений и интеграции с роботом без использования ISRA.

## 2. Принятые решения по оборудованию и ПО

### 2.1. Сохраняемое оборудование
- **Промышленный ПК** – Siemens SIMATIC IPC547G (Windows 7 64-bit). Он достаточно мощный и уже имеет установленные драйверы для платы cifX.
- **Рабочее расстояние и FOV** – сохраняем (≈100–120 мм, FOV 100×100 мм).
- **Интерфейсная плата cifX** – сохраняем для использования PROFINET в качестве основного канала связи с роботом (и PLC). Это позволит минимизировать изменения в существующей инфраструктуре.

### 2.2. Заменяемое оборудование
- **Датчик ISRA** – заменяем на **промышленную камеру Hikrobot** (например, серии MV-CS или MV-CA) с соответствующим объективом и отдельной системой освещения (кольцевой светодиодный источник с контроллером).

### 2.3. Программное обеспечение на ПК
- **Операционная система**: Windows 7 64-bit (оставляем).
- **Среда разработки**: Python 3.8.10 (последняя версия, поддерживающая Windows 7).
- **Библиотеки**:
  - OpenCV (`pip install opencv-python`).
  - NumPy (`pip install numpy`).
  - PyModbus (`pip install pymodbus`) — для связи с OWEN MK210.
  - PyInstaller (`pip install PyInstaller`) — для создания .exe.
- **Камера Hikrobot**: работает через Modbus-триггер + чтение JPEG из папки (без MVS SDK в Python).
- **Обмен с роботом**:
  - **Тестовый стенд**: Modbus TCP с OWEN MK210 (192.168.1.99:502).
  - **KUKA KRC4**: OpenShowVar (KUKAVARPROXY, порт 7000) или PROFINET через cifX (планируется).

### 4.2. Реализованный алгоритм

Система работает следующим образом:

1. **Захват**: Modbus-триггер → камера сохраняет JPEG в папку → Python читает последний файл
2. **Обработка**: ROI crop → CLAHE (clipLimit=5.0) → GaussianBlur (5×5) → Otsu threshold → MorphClose (15×15) → MorphOpen (5×5) → findContours
3. **Измерение**: `width_mm = min(w, h) / px_per_mm` (min bounding rect = ширина шва)
4. **Решение**: OK если `min_width_mm ≤ width_mm ≤ max_width_mm` (1.0–6.0 мм)
5. **Отправка**: DO3 (зелёная) = OK, DO2 (красная) = NG

Пример ключевого кода обработки (`image_processor.py`):
```python
def process(self, image):
    cropped, offset_x, offset_y = self._crop_to_roi(image)
    gray = cv2.cvtColor(cropped, cv2.COLOR_BGR2GRAY)
    clahe = cv2.createCLAHE(clipLimit=5.0, tileGridSize=(8, 8))
    enhanced = clahe.apply(gray)
    blur = cv2.GaussianBlur(enhanced, (5, 5), 0)
    val, thresh = cv2.threshold(blur, 0, 255, cv2.THRESH_BINARY_INV + cv2.THRESH_OTSU)
    kernel_close = cv2.getStructuringElement(cv2.MORPH_RECT, (15, 15))
    kernel_open = cv2.getStructuringElement(cv2.MORPH_RECT, (5, 5))
    cleaned = cv2.morphologyEx(thresh, cv2.MORPH_CLOSE, kernel_close)
    cleaned = cv2.morphologyEx(cleaned, cv2.MORPH_OPEN, kernel_open)
    contours, _ = cv2.findContours(cleaned, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    # ... фильтрация и измерение
    width_mm = min(w, h) / self.px_per_mm
    ok = self.min_width <= width_mm <= self.max_width
    return ok, width_mm, msg, bbox
```

### Маппинг I/O ОВЕН МК210 (актуальный)

| DI | Назначение          | DO | Назначение         |
|----|---------------------|----|--------------------|
| DI0| Датчик Д1 (конвейер)| DO0| Конвейер (пуск/стоп)|
| DI1| Датчик Д2 (камера)  | DO1| Толкатель (резерв)  |
| DI2| Датчик Д3 (камера)  | DO2| Лампа NG (красная)  |
| DI3| Датчик Д4 (выход)   | DO3| Лампа OK (зелёная)  |
| DI4| Тумблер A (старт)   |    |                    |
| DI5| Тумблер B (конец)   |    |                    |
| DI6| Датчик Д6 (захват)  |    |                    |

### 4.3. Калибровка
- Сфотографировать объект известного размера (калибровочную линейку) при рабочем расстоянии.
- Вычислить коэффициент px_per_mm = (ширина в пикселях) / (реальная ширина в мм).

### 4.4. Оптимизация производительности
- Использовать NumPy для векторных операций.
- Избегать циклов на Python по пикселям.
- Если требуется высокая скорость, рассмотреть C++ или использование GPU (CUDA), но для 0.8 с/кадр Python достаточно.

## 5. Интеграция с роботом и PLC

### 5.1. Реализованный способ: Modbus TCP (OWEN MK210)

Для тестового стенда используется **OWEN MK210** (Modbus TCP, 192.168.1.99:502).

#### Конфигурация Modbus:
- **Входной регистр**: 51 (чтение DI)
- **Выходной регистр**: 470 (запись DO)
- **DI биты**: di04=4 (Тумблер A), di05=5 (Тумблер B), di06=6 (Датчик Д6)
- **DO биты**: do00=0 (конвейер), do01=1 (толкатель), do02=2 (NG), do03=3 (OK)

#### Цикл работы:
1. Ожидание DI04 (Тумблер A — старт)
2. Ожидание DI06 (Датчик Д6 — захват)
3. Modbus-триггер камере → JPEG в папку
4. Обработка изображения → замер ширины
5. send_result(): DO3 (OK) или DO2 (NG)
6. Ожидание DI05 (Тумблер B — конец)
7. reset_outputs() → возврат к шагу 1

### 5.2. Альтернативный способ: OpenShowVar (KUKAVARPROXY)

Для связи с KUKA KRC4 используется **OpenShowVar** (raw socket, порт 7000).

**Установка на робот**:
1. Скопировать папку `OpenShowVar` на SmartPad
2. Запустить `KUKAVARPROXY.exe` (сервер, порт 7000)
3. Настроить брандмауэр: разрешить порт 7000

### 5.3. План: PROFINET через cifX (будущее)

Плата cifX PCI/PCIe установлена в ПК. Планируется использование PROFINET Device для обмена с KUKA KRC4.

## 6. Создание исполняемого файла (.exe) и развертывание

### 6.1. Установка PyInstaller
```cmd
pip install pyinstaller
```

### 6.2. Сборка
Перейти в папку со скриптом `main.py` и выполнить:
```cmd
pyinstaller --onefile --add-data "путь_к_калибровочным_файлам;." main.py
```
- `--onefile` – один .exe.
- `--add-data` – если есть внешние файлы (калибровка, конфиги).

### 6.3. Проверка на целевом ПК
- Установить Visual C++ Redistributable 2015-2022.
- Установить MVS (драйверы камеры).
- Установить драйверы cifX (если ещё не установлены).
- Скопировать .exe и запустить из командной строки для отладки.

### 6.4. Автозагрузка
- Через планировщик задач Windows: создать задачу с запуском при старте системы, с наивысшими привилегиями.
- Или поместить ярлык в папку `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`.

## 8. Возможные сложности и их решения

| Сложность | Решение |
|-----------|---------|
| Камера Hikrobot не определяется в Windows 7 | Установить обновления KB4474419 и KB4490628; проверить версию MVS (5.x). |
| PyInstaller не собирает библиотеки Hikrobot | Вручную скопировать DLL из папки MVS в папку с .exe или использовать `--add-binary`. |
| PROFINET через cifX не работает | Проверить драйверы, настройки IP-адресов, конфликт с другими устройствами. Воспользоваться альтернативными способами (OpenShowVar). |
| Алгоритм даёт ложные срабатывания | Настроить пороги, добавить морфологическую обработку, использовать адаптивную пороговую обработку. |
| Недостаточная скорость обработки | Оптимизировать код (использовать Cython, сократить разрешение, перейти на C++). |
| Отсутствие контроля связи (keep-alive) при использовании PROFINET | PROFINET сам обеспечивает контроль связи (watchdog). Для других способов реализовать проверку счётчика в KRL. |
| Ошибки при запуске .exe | Запускать из командной строки для чтения сообщений об ошибках; проверить наличие всех DLL. |
